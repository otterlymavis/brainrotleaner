# FocusVid landing + creator review

Reviewed the live local prototype at `http://127.0.0.1:4173/` using the in-app browser.

## Captured steps

1. Landing page at mobile width: hero, CTA, navigation, and visual hierarchy.
2. Primary CTA into creator: Quick Create material step rendered with example cards and summary.
3. Creator progression: `Next: Mode` advances to the mode step successfully.
4. FAQ: accordion expansion is visible and readable.
5. Gallery: local video card toggles from play to pause state.
6. Desktop layout bounds and console: no browser warnings/errors; layout bounds are centered and responsive.

## Findings

- P1: The mobile menu button opens the creator directly instead of exposing navigation. Users cannot reach Features, How it works, or FAQ from the mobile header without scrolling.
- P2: The Quick Create progress strip labels future steps as “complete” even before the user configures them. This creates misleading progress feedback.
- P2: The landing gallery repeats the same two local videos under different labels. It works technically, but the repeated media makes the product feel less finished.
- P3: The landing page and creator use different visual systems: the landing page is polished and marketing-led while the creator is denser and more utility-like. A shared token pass would improve continuity.

## Accessibility limits

Heading structure, button/link semantics, and accordion state were visible in the accessibility tree. Full keyboard traversal, screen-reader announcements, reduced-motion behavior, and PDF/upload error handling were not exhaustively tested in this review.
