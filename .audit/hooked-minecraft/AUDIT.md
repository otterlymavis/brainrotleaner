# Hooked Minecraft Parkour Video audit

Captured 2026-09-02 from https://www.hooked.so/tools/minecraft-parkour-video.

## Steps

1. Start state — strong visual hierarchy, clear CTA, but the promotional toast overlaps the editor.
2. Script entered — live word count and duration estimate are useful; the editor is large and easy to scan.
3. Gameplay selected — media cards and selected-state feedback are clear; the horizontal card rail is awkward on a desktop viewport.
4. Background selected — category tabs and image choices make the background decision concrete; the output preview remains partially visible and secondary.
5. Advanced settings — aspect ratio, captions, presets, and alignment are discoverable; the large preset grid creates a long scroll and the promo toast obscures controls.

## High-impact findings

- Keep the quick-create workflow and readiness summary as the primary path.
- Add a true split-screen preview with draggable content/gameplay proportions.
- Add an explicit “story beat → jump” timeline so synchronization is understandable and editable.
- Add caption safe-area warnings for portrait output and preview on the selected platform frame.
- Add saved style presets that bundle caption, layout, voice, music ducking, and intensity.
- Add a lightweight trend/inspiration starter library rather than a full trends product.
- Add export presets and publishing handoff only after the editor feels stable.

## Limits

This was a visual and interaction audit of the unauthenticated page. I did not submit account forms, render a paid video, test server-side generation, verify licensing, or validate keyboard/screen-reader behavior end to end.
